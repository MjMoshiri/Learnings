# Designing Data-Intensive Applications

Martin Kleppmann. The spine is trade-offs. Most architecture questions have no single right answer, just options with different costs.

## Covered

- `trade-offs.md` — Ch 1. OLTP vs OLAP, warehouse vs lake (sushi principle), why go distributed, privacy as architecture.
- `non-functional-requirements.md` — Ch 2. Percentiles and adding histograms, reliability vs cost, essential vs accidental complexity, maintainability.
- `data-models-and-query-languages.md` — Ch 3. Declarative queries, impedance mismatch, when to denormalize, schema-on-read vs write, Cypher vs SQL, event sourcing and CQRS.
