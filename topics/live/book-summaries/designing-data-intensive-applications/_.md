# Designing Data-Intensive Applications

Martin Kleppmann. The spine is trade-offs. Most architecture questions have no single right answer, just options with different costs.

## Covered

- `trade-offs.md` — Ch 1. OLTP vs OLAP, warehouse vs lake (sushi principle), why go distributed, privacy as architecture.
- `non-functional-requirements.md` — Ch 2. Percentiles and adding histograms, reliability vs cost, essential vs accidental complexity, maintainability.
- `data-models-and-query-languages.md` — Ch 3. Declarative queries, impedance mismatch, when to denormalize, schema-on-read vs write, Cypher vs SQL, event sourcing and CQRS.
- `storage-and-retrieval.md` — Ch 4. Log-structured vs B-trees, SSTables, tombstones, Bloom filters, column stores, bitmap encoding, vectorization vs compilation, multidimensional/inverted/vector indexes (IVF, HNSW).
- `encoding-and-evolution.md` — Ch 5. Forward vs backward compatibility, JSON Schema (additionalProperties, patternProperties, pg_jsonschema), Protobuf field tags, Avro writer/reader schemas, dataflow modes (DB, RPC/REST, event-driven), service discovery and meshes, durable execution, the actor model.
- `replication.md` — Ch 6. Single-leader (sync/semi-sync/async, failover pitfalls), replication log types, lag anomalies (read-your-writes, monotonic reads, consistent prefix), multi-leader conflicts (LWW, CRDTs, OT), leaderless quorums (read repair, sloppy quorum, hinted handoff), version vectors.
- `sharding.md` — Ch 7. Key-range vs hash sharding, skew and hot keys (suffix trick), rebalancing (fixed shard count, dynamic splits, consistent hashing, never mod N), request routing (ZooKeeper, gossip), local vs global secondary indexes.
