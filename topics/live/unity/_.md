# unity basics

## mental model

Unity is a scene graph plus a frame loop. You compose GameObjects out of Components. You write Components (MonoBehaviour scripts in C#) and the engine ticks them every frame. That's the whole engine in one sentence.

## GameObject + Component

A GameObject is an empty container. It has a Transform (position, rotation, scale) by default and nothing else. All behaviour comes from Components attached to it: MeshRenderer, Collider, Rigidbody, AudioSource, your own scripts.

Composition, not inheritance. You don't subclass `Enemy : Character`. You attach a `Health` component, a `Movement` component, an `EnemyAI` component to a GameObject.

## Prefab

A GameObject saved as an asset. Spawn many copies of it (enemies, bullets, trees). Edit the prefab once, every instance updates. Override per-instance fields when you need to.

## Scene + Hierarchy

Scene = the loaded world, stored as a `.unity` file. Hierarchy panel shows the tree of GameObjects in the active scene. Parent a GameObject under another and its Transform becomes relative to the parent's.

## Assets

Anything on disk under `Assets/`:

- meshes (`.fbx`, `.obj`)
- textures (`.png`)
- materials (shader + texture params)
- audio clips (`.wav`, `.mp3`, `.ogg`)
- animations, shaders, scripts, prefabs, scenes

The AssetDatabase imports and tracks them. Project panel is the file browser for assets.

## Camera

A Component on a GameObject. `Camera.main` is the one tagged `MainCamera`. Perspective or orthographic projection, near/far clip planes, FOV, optional target render texture. Move the GameObject, you move the viewpoint.

## Skybox

Environment background. A Skybox material (cubemap or procedural) assigned in `Window > Rendering > Lighting > Environment`. The camera renders it behind everything when its Clear Flags is set to Skybox.

## Terrain

Specialised component for landscapes. Heightmap-based mesh with tools to paint height, textures, trees, grass, detail meshes. Lives on a GameObject with a Terrain + TerrainCollider component.

## Audio

`AudioSource` plays an `AudioClip` from the GameObject's position. `AudioListener` (usually on the main camera) is the mic. The engine handles 3D spatialisation based on positions.

## Scripting: connecting Components

A `MonoBehaviour` script becomes a Component when attached to a GameObject. Lifecycle hooks:

- `Awake()` once on load, before anything else. Wire up internal refs.
- `Start()` once, just before the first frame. Safe to talk to other objects.
- `Update()` every frame. Input, gameplay logic.
- `FixedUpdate()` fixed timestep, default 50 Hz. Physics goes here.
- `LateUpdate()` after all Updates. Camera follow lives here.

Ways to grab other Components:

- `[SerializeField] private Rigidbody rb;` then drag the ref in the Inspector. Preferred.
- `GetComponent<Rigidbody>()` on the same GameObject.
- `GetComponentInChildren<T>()` / `GetComponentInParent<T>()`.
- `FindObjectOfType<T>()` scene-wide. Slow. Don't put it in hot loops.

For cross-script communication: `UnityEvent`, plain C# events, or a small message bus.

## Rigidbody

The Component that makes a GameObject obey physics. Stop writing `transform.position += ...`. Let the physics engine integrate forces instead.

Key fields:

- `mass`, `drag`, `angularDrag`
- `useGravity`
- `isKinematic` true means physics ignores it. You script its motion but it still pushes other Rigidbodies on collision.
- `interpolation` smooths visual motion between physics steps
- `constraints` freeze position or rotation axes

Apply forces with `rb.AddForce()`. Set velocity with `rb.linearVelocity`. Do this in `FixedUpdate`. 2D version is `Rigidbody2D`.

## Time.deltaTime

Seconds since the last frame finished. Multiply any per-frame change by it so motion is framerate-independent:

```csharp
transform.position += direction * speed * Time.deltaTime; // metres/sec, not metres/frame
```

`Time.fixedDeltaTime` is the fixed physics step. Inside `FixedUpdate` use that, or trust Unity to call it at the right cadence.

## putting it together: minimal example

```csharp
using UnityEngine;

public class PlayerMover : MonoBehaviour
{
    [SerializeField] private Rigidbody rb;
    [SerializeField] private float speed = 5f;

    private Vector3 move;

    void Update()
    {
        float h = Input.GetAxis("Horizontal");
        float v = Input.GetAxis("Vertical");
        move = new Vector3(h, 0f, v);
    }

    void FixedUpdate()
    {
        rb.linearVelocity = move * speed;
    }
}
```
